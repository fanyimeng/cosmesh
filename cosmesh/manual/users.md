# 实名用户目录与贡献总览

## 登录与实名

登录继续复用本人服务器账号和 SSH，Hub 通过内核或已核验 SSH 身份确认提交者。首次访问启用用户目录的 Hub 自动获得永久 person- ID，姓名初始留空；共享写入前由本人填写真实姓名。系统确认账号归属，姓名标注本人填写，不声称核验过身份证件。

user me --require-fresh 查看本人状态；缺少姓名时，Agent 简短询问本人真实姓名，收到回答即可 user set-name NAME 保存，不从账号、显示名或其他聊天猜测。姓名用于组内目录与优先展示。已有姓名变更需先读版本，再 set-name NEW_NAME --expect VERSION，稳定用户 ID 与历史贡献保持。

个人 Base 可独立离线工作，私人 Profile 仍保持原范围。共享目录仅含用户 ID、服务器账号、本人姓名、成员/维护者角色及在用/停用状态；Profile 的联系方式、机构和偏好不自动公开。

## 用真名找人和发请求

user list 查看成员，user show REAL_NAME 查询一个人。thread request WORK_ID --to REAL_NAME 可以直接用本人填写的姓名；user overview REAL_NAME --require-fresh 汇总其共享工作、收到的请求、资料版本与贡献活动。

匹配优先使用明确账号或稳定用户 ID，其次对完整实名做规范化精确匹配。重名返回 AMBIGUOUS_USER 和候选的姓名/账号/ID，由用户选择；未找到时列出目录供定位，不凭相似姓名自动选人。未填写实名的接收人先完成本人登记。

默认缓存查询带截至时间；要求最新状态时 --require-fresh 只拉取。当前目录只包含已经访问这个 Hub 或具有已接受共享记录的账号，不扫描全部操作系统账号，也不猜测真实姓名。

## 用户状态与角色

角色仅 member/admin。普通成员读共享资料、创建本人记录、回应请求；内容概况、资料维护与请求采用仍依据具体对象的作者/维护关系。

user manage PERSON --expect VERSION --status active|disabled 或 --role member|admin 由维护者执行。禁止停用或降级最后一名在用维护者。停用阻止该 Hub 的新读取和写入，保留历史署名；重新启用保留相同 person ID。离组时可交接资料维护责任，历史作者保持原人。

管理员管理用户与系统，不从该角色获得冒充作者、改写已接受工作或替请求人采用结果的资格。服务器管理员的实际文件系统权限另按运维职责管理。已缓存副本的范围保持其原有属性，远端停用不远程删除个人文档。

现有账号改绑、机构单点登录和跨 Hub 合并身份尚未实现。本版支持本人实名变更、角色/状态管理和资料维护交接；历史账号署名保留，稳定身份在新记录中由服务器核验。
